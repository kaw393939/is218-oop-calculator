## Type and run

The workflow uses YAML, where indentation expresses structure. Read each section before typing:

| Section | Meaning |
| --- | --- |
| `on` | Run on pushes, pull requests, or manual requests. |
| `permissions` | Give the job read access to the repository. |
| `jobs` and `runs-on` | Define work to execute on a fresh Ubuntu runner. |
| `strategy.matrix` | Repeat the work on Python 3.11, 3.12, 3.13, and 3.14. |
| `uses` | Invoke an action to download code or install Python. |
| `run` | Execute a shell command. |

`${{ matrix.python-version }}` supplies the version for each job. The steps check out code, install Python, install requirements, and run `python -m pytest`. `pytest.ini` supplies the coverage gate, so either a failed test or insufficient coverage makes the job fail. This does not deploy the app or configure required merge checks.

Run `python -m pytest` locally. Commit the new workflow and your README. Create an empty GitHub repository under your account, then publish your solution:

```bash
git add .github/workflows/tests.yml README.md
git commit -m "Stage 6: automate calculator checks"
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the URL with your repository details. If `origin` already points to your solution repository, skip adding it again; inspect it with `git remote -v`. Do not push your coursework into the instructor's reference repository. GitHub may require authentication.

Open **Actions → Calculator tests** in your repository. All four jobs should pass. To understand a failure, open the failing step, find the relevant assertion or coverage message, and reproduce it locally. The manual **Run workflow** option becomes available once the workflow is on your default branch.

## Explain and experiment

Read [the bigger picture](../bigger-picture.md). Use its history and examples to name ideas you already used; you do not need to memorize dates or implement every pattern.

Write a short reflection in your README:

1. How would you add `Multiply`? Identify affected files, including registration, help, and tests, and explain why History should not need new arithmetic logic.
2. Imagine email and text-message notification objects sharing `send()`. What behavior must their caller be able to rely on?
3. Which concepts transfer to another OOP language, and which syntax or runtime rules would you still need to learn?

An optional extension can implement multiplication after the baseline passes. It is not required and should include behavior assertions.
